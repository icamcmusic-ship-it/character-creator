## B. Bugs seen (verified in browser)

- B-1 P1 `js/render.js:463` (`.exampleLine`), `js/render.js:719` (`.summaryVoice`), also sample lines in voice lab. Trait data deliberately holds stage directions as `<i>(…)</i>` (596 lines in js/data/*.js, e.g. traits-balance.js:119 "Stands at forty-five degrees") but the renderer passes them through `escHTML`, so users read literal markup: `“<i>(eyes narrowed)</i> Hm. Say that again.”` and in the headline voice sample `…<i>(an enormous laugh at a very small remark)</i>`. Evidence: q1.mjs counts 4-8 literal `<i>`/`</i>` strings in innerText after one default build at 1440/390/dark; shots/m390-03-card.png (top of screenshot). Fix: after escHTML, restore only `&lt;i&gt;`/`&lt;/i&gt;` to real `<i>`/`</i>` (whitelist), or strip tags for plain-text copy/export (check Copy/Export also shows literal tags).
- B-2 P1 css/style.css:277 `.traitDesc{color:#3d4f61}` and :1137 `.traitDesc{color:#4a4360}` are hard-coded and not overridden for dark mode. Computed in dark: rgb(74,67,96) on card rgb(30,26,43) = 1.83:1 on every card; the one-line description (the most important text on a card) is almost invisible. Evidence shots/q1-dark-card.png (description line is barely visible), scan-out dark-1440 `.traitDesc` n=45. Same cause (hard-coded light-theme colours): `li` in the conflict warn box (1.9:1), `.conflictNote/.conflictCount` (1.8:1), `.contraDerived/.chainFrom/.chainCount/.ctxHeadline` rgb(107,122,138) on dark (3.6:1). Fix: use theme tokens (var(--muted)/var(--text-2)) everywhere; add a lint (grep for `#[0-9a-f]{6}` colour in color: declarations outside :root).
- B-3 P1 Dark theme bottom action bar (`.stickyBar`/`stickySeed`, shots/q1-dark-card.png, first-dark-1440-vp.png): bar background stays light lavender rgb(228,226,233) in dark mode while the page is near-black, with dark pills on it; muted seed text on it is 2.2:1. Looks like a missed dark override; jarring glare strip pinned to the bottom of every dark screen. Fix: give the bar a themed surface token.
- B-4 P1 Layout shift on every load (CLS): 0.10 at 1440, 0.18 at 1024, 0.21 at 768, **0.54 at 390/320** — cls.mjs. Sources: `.helpPanel`/`view-single` jump down 269->472 (390: 249->569) after first paint, `headTools` 117->138 and `tabs` 166->187 at 390 (header tool row reflows as the project chip/theme label render), and the form `.field`/dialBox rows. Poor-field-data threshold is 0.25. The onboarding card ("New here?") being injected by JS after paint pushes the whole form down and a user about to tap a control hits something else. Fix: render onboarding card server-side in HTML (hidden via a class set in an inline <head> script from localStorage), reserve header heights (min-height on `.headTools`), set explicit width for the theme button label ("Auto").
- B-5 P2 After a build on desktop, each trait card is ~340px tall though its content is ~150px (shots/q1-dark-card.png): the right-hand action column stacks Toss/Keep/pin/why?/★/📌/🚫/■/+ note vertically and sets the card height; large blank gap under the "Use:" line. 44 cards -> page height 27,765px at 1440 and 34,345px at 390 (q1.mjs). Fix: lay the 4 icon-only mark buttons in a row (or in the ⋯ popover, as on phone) and let the column wrap; collapses height roughly in half.
- B-6 P2 Icon-only mark buttons (★ 📌 🚫 ■) at desktop are 1-glyph with no visible label; tooltip/aria only (check). 3 of the 4 glyphs are emoji that render differently per OS; `■` for "retire" is not guessable. Fix: visible text or an explained legend on first open.
- B-7 P1 "Roll 5, pick one" (and probably "keep the most different", "same world", etc.) as the FIRST action, before any Build: `.batchGrid` is rendered inside the full sheet chrome of a character that does not exist. Screens (shots/q5-batch.png, q4-roll5-form.png): "Your hand 79%", heading "Character Voice", archetype pill "Fighter Who Keeps a Ledger *" (= last candidate), banner "Mostly distinct to your last generation — 2% of traits shared…" (there was no last generation), an amber trait-tension warning for a candidate nobody chose, the sheet-nav chips, Lock all/Unpin all/Collapse buttons, then 11 section stubs each reading "Nothing was drawable here at these settings. Ease a constraint or widen the slider precision." (q5.mjs: 11 matches; page 4,442px -> 9,285px), while the sticky bar still says "no character yet". The scroll lands ~600px short/over of the grid (viewport top=5861, grid at doc y 6504; a later run measured grid top -506 after the 1.8s settle, i.e. above the fold). Fix: when `lastState` is null render ONLY the batch panel (hide `#output` chrome and empty-group stubs); never show the "Nothing was drawable" copy for groups of an unbuilt sheet; scroll to `.batchGrid` after layout settles (rAF x2), and show one voice-sample line per candidate so "pick one" is an informed choice.

Flip Tinker Mode off any time for the short version." was still on screen ~2 s+ later over unrelated content (q5-batch.png, bottom right) and sits over the sticky-bar region on phone; toasts with an × need auto-dismiss (~5-6 s) or pause-on-hover; confirm timeouts (the lock/toss toasts in j1 were not seen at all, see F-section).

## H. Performance (perf.mjs, t1.mjs, q1.mjs, sw1.mjs)
- H-1 P1 Fonts: `index.html` loads Google Fonts CSS render-blocking. With the font host black-holed for 4 s (4x CPU throttle) first/largest contentful paint is 4,468 ms vs 588-856 ms with it quick/blocked immediately (perf.mjs). On offline or corporate-proxy machines (this sandbox: `ERR_CERT_AUTHORITY_INVALID`) every load pays that. Fix: self-host a 2-weight subset with `font-display:swap` + `<link rel=preload>`, or drop to system stacks; remove `display=swap` dependency on a blocking stylesheet (`media="print" onload`).
- H-2 P1 Main-thread: 3 long tasks totalling ~955 ms (max 636 ms) at load on desktop; 4x CPU: ~890 ms, max 543 ms. First build: ~970 ms desktop, **2.9 s at 4x CPU** (mid-range phone) with no spinner longer than the button state (check). JS payload 4.2 MB decoded over 24 requests (traits-core 1.26 MB, engine 600 KB, supplement 536 KB, life 436 KB, app.js 254 KB; sw1.mjs) and `app.js` evaluation takes ~1.1 s. Fix: gzip/brotli at host (python server doesn't, so numbers here are upper bound), lazy-load unused trait sections (off sections are 13 of 28), split data into `defer` scripts after first paint.
- H-3 P1 DOM weight: unbuilt 2,423 nodes / 147 buttons / 203 inputs / 16 `<details>`; after one build 5,076-5,212 nodes, 652-676 buttons (≈9 per card), page 27-34k px, 664 tab stops.
